# 파이프라인 캔버스 UX

파이프라인을 사람이 만드는 화면. **React Flow(`@xyflow/react`)** 로 만든다.

콘솔(에디터/결과/사이드바 3분할)과는 다른 별도 화면이다. 기존
[프런트엔드 컨벤션](../conventions/frontend-react.md)은 그대로 적용된다 — 특히 **자격증명은
화면에 나타나지 않는다**: 노드의 커넥션 설정은 저장된 접속 이름만 고르게 하고, 비밀번호 입력
필드를 두지 않는다.

## 화면 구성

```
┌──────────┬────────────────────────────────┬──────────────┐
│ 팔레트    │  캔버스 (React Flow)            │ 설정 패널     │
│ 노드 목록 │  노드 · 엣지 · 그룹 영역         │ 선택 노드 편집 │
└──────────┴────────────────────────────────┴──────────────┘
                   실행 바 (전체 실행 · 노드 미리보기 · 진행률)
```

- **팔레트**: 드래그해서 캔버스에 떨어뜨린다. 드래그 중 프리뷰를 보여준다.
- **설정 패널**: 선택된 노드의 필드. 필드 선언은 `connectorFields.ts`에서 오고, 백엔드 허용 키와
  짝을 이룬다 ([connector-contract.md](connector-contract.md)). **커넥션 선택 목록은 `role`과
  `adapter_type` 양쪽으로 좁힌다** — `target.s3` 노드에는 `role='target'`인 `s3` 커넥션만 뜬다
  ([dag-and-nodes.md](dag-and-nodes.md)의 대응표). 고를 수 있게 보여준 뒤 저장에서 거부하지 않는다.
- **실행 바**: 전체 실행 / 선택 노드 미리보기 / 진행률 · 노드 상태.

## 편집 기능

| 기능 | 비고 |
|---|---|
| 노드 이동 · 삭제 | 휴지통 드롭 또는 `Del` |
| 복사 · 붙여넣기 | 엣지 관계까지 함께 |
| 되돌리기 (`Ctrl+Z`) | 스냅샷 히스토리 |
| 그룹 영역 | 제목 · 색상 · 리사이즈 · 그룹째 이동 |
| 엣지 결과 미리보기 | 노드 미리보기 실행 후 그 엣지를 흐른 샘플 행 |

## 노드 미리보기는 타깃에 쓰지 않는다

"선택 노드만 실행"은 **소스·변환 노드 전용 미리보기**다. 앞 체인을 샘플 몇 배치만 흘려보고
결과를 보여줄 뿐, **타깃 노드에는 적용되지 않는다.**

- 타깃 노드를 고르면 미리보기 버튼은 비활성이고, 왜 안 되는지 화면에서 말해준다.
- 미리보기는 실행 이력(`pipeline_runs`)을 만들지 않고 워터마크도 전진시키지 않는다.
- **저장하지 않은 초안에서는 버튼이 비활성**이다. 감사 기록이 어느 파이프라인의 것인지 가리킬 수
  없기 때문이다. 반대로 **저장된 파이프라인을 편집 중일 때는 눌린다** — 쿼리를 고쳐가며 돌려보는
  것이 미리보기의 존재 이유다.
- **누를 때마다, 읽은 커넥션마다 감사 로그에 한 건 남는다**(`pipeline_trigger='preview'`). 상류
  소스가 둘이면 두 건이다. 저장하지 않은 편집이
  있으면 그 기록의 `pipeline_version`은 NULL이다 ([audit-logs.md](../schema/audit-logs.md)).

**타깃에 쓰는 경로는 전체 실행 하나뿐이다.** 미리보기로 쓰기가 가능해지면 실행 잠금·감사 기록을
비껴가는 두 번째 쓰기 통로가 생긴다 ([execution-engine.md](execution-engine.md),
[pipeline-write-boundary.md](../policy/pipeline-write-boundary.md)).

## 되돌리기는 스냅샷 히스토리로

캔버스 편집 상태는 **zustand 스토어에 스냅샷 히스토리**로 관리한다. 조작마다 diff를 계산하는
방식보다 단순하고, 캔버스 크기에서는 스냅샷 비용이 문제되지 않는다.

**묶음 규칙이 핵심이다.** 이걸 안 하면 `Ctrl+Z` 한 번이 아무 의미 없는 단계로 되돌아간다.

- **드래그는 한 단계다.** 이동 중 발생하는 수십 번의 위치 변경을 각각 기록하지 않는다.
- **연속 타이핑은 한 단계다.** 노드 이름을 고치는 동안 글자마다 기록하지 않는다.
- **삭제는 한 단계다.** React Flow는 노드 삭제와 그에 딸린 엣지 삭제를 **별도 변경 이벤트로**
  보낸다. 이 둘을 병합하지 않으면 `Ctrl+Z` 한 번에 노드만 살아나고 엣지는 안 살아난다.

## 알려진 함정 (React Flow)

원본 청사진에서 실제로 밟았던 것들이다. 같은 라이브러리를 쓰므로 그대로 유효하다.

### `elevateNodesOnSelect={false}`로 둔다

기본값(`true`)이면 선택된 노드가 앞 레이어로 올라온다. 그룹 영역은 뒤 레이어에 있는 큰 노드인데,
그룹을 한 번 선택하면 앞으로 올라와서 **그 위에 놓인 노드들의 클릭을 가로챈다.** 그룹을 골랐더니
안의 노드를 더 이상 못 만지는 증상이 된다.

### 엣지 라벨·결과 칩은 `z-index`로 올린다

React Flow의 엣지 레이어는 노드 레이어보다 **아래**다. 엣지에 붙인 라벨이나 결과 미리보기 칩이
큰 노드에 덮여 안 보인다. 해당 요소만 명시적으로 `z-index`를 올린다.

### 좌표는 캔버스 좌표계로 저장한다

노드 위치를 화면 픽셀로 저장하면 줌·팬 상태에 따라 달라진다. React Flow가 주는 **flow 좌표**를
그대로 저장한다.

## 실행 중 화면

- 노드 상태(대기 · 실행중 · 성공 · 실패)를 노드 테두리 색으로 표시한다.
- 진행률·로그는 **WebSocket으로 push** 받는다. 폴링하지 않는다
  ([execution-engine.md](execution-engine.md)).
- 실패한 노드를 클릭하면 그 노드의 에러와 로그로 바로 간다. 로그 전체에서 찾게 만들지 않는다.
- 실행 중에는 편집을 막지 않되, **저장은 새 버전으로** 올라간다. 진행 중인 실행은 시작 시점
  정의로 끝까지 간다 ([dag-and-nodes.md](dag-and-nodes.md)).
