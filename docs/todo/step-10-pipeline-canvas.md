# STEP 10 · 파이프라인 캔버스

**시작 조건**: STEP 9 (+ STEP 2의 프런트엔드 골격)

## 목표

STEP 9에서 만든 실행 능력에 **사람이 쓸 수 있는 화면**을 붙인다. 드래그앤드롭으로 파이프라인을
구성하고, 실행하고, 진행 상황을 본다.

**심사에서 실제로 보여줄 화면이다.** F7의 차별점은 "데이터를 옮길 수 있다"가 아니라 "옮기는 걸
눈으로 짜고 눈으로 본다"에 있다.

## 하는 일

- React Flow(`@xyflow/react`) 캔버스 — 팔레트 · 노드 · 엣지 · 설정 패널
  ([canvas-ux.md](../pipeline/canvas-ux.md))
- 노드 설정 필드 선언(`connectorFields.ts`)을 **백엔드 허용 키와 짝으로** 관리
- **자격증명은 화면에 나타나지 않는다** — 커넥션은 저장된 이름으로만 고른다
  ([frontend-react.md](../conventions/frontend-react.md))
- 타깃 노드의 커넥션 선택 목록에는 **`role='target'`만** 나온다
- 편집: 이동 · 삭제(휴지통/`Del`) · 복사·붙여넣기 · `Ctrl+Z` 되돌리기
- zustand 캔버스 스토어 + **스냅샷 히스토리** — 드래그·연속 타이핑은 한 단계, 노드+엣지 삭제도
  한 단계로 병합
- 그룹 영역(`note.group`) · 메모(`note.memo`) — 실행·검증에서 `NOTE_KINDS`로 일괄 제외
- 실행 바: 전체 실행 · 노드 미리보기 · `full_refresh` 옵션
- **노드 미리보기는 소스·변환 노드 전용이다** — 타깃 노드는 단독 실행할 수 없고, 미리보기는 실행
  이력을 만들지도 워터마크를 전진시키지도 않는다 ([execution-engine.md](../pipeline/execution-engine.md))
- **WebSocket 실시간 표시** — 노드 상태 색, 진행률, 로그 스트림 (폴링하지 않는다)
- `pipeline_run_logs` 조회 화면 — 실패 노드 클릭 시 해당 에러로 바로 이동
- 실행 이력 목록 (`pipeline_runs`) + 실행 상세

## 알려진 함정 (미리 챙긴다)

- `elevateNodesOnSelect={false}` — 안 그러면 그룹 영역을 선택한 순간 그 위 노드들의 클릭을
  가로챈다
- 엣지 라벨·결과 칩은 노드 레이어보다 아래라서 큰 노드에 덮인다 → `z-index`로 올린다
- 노드 좌표는 화면 픽셀이 아니라 **flow 좌표**로 저장한다

자세한 배경은 [canvas-ux.md](../pipeline/canvas-ux.md).

## 완료 조건

1. 브라우저에서 소스 → 타깃 파이프라인을 **드래그앤드롭으로 만들고 저장**한다.
2. 저장한 파이프라인을 화면에서 실행하고, **노드 상태와 진행률이 실시간으로 갱신**된다.
3. 실패한 실행에서 **어느 노드가 왜 실패했는지** 화면만 보고 안다.
4. `Ctrl+Z` 한 번이 노드 삭제를 **엣지까지 함께** 되돌린다.
5. 타깃 노드의 커넥션 목록에 소스 커넥션이 **나타나지 않는다.**
6. 어느 화면에서도 비밀번호 입력·표시 필드가 없다.
7. 타깃 노드를 선택하면 **미리보기 실행이 불가능**하고, 화면이 그 이유를 알려준다. 미리보기로는
   타깃에 한 행도 쓰이지 않는다.
