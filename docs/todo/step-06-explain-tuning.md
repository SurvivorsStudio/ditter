# STEP 6 · EXPLAIN 해석 + 튜닝 제안 (`F4` 완성)

**시작 조건**: STEP 5

## 목표

"발견"을 "개선"으로 잇는다. 느린 쿼리를 넣으면 **왜 느린지**를 사람 말로 설명하고, **어떻게 고칠지**를 제안한다. 인덱스를 추가하라거나, 쿼리를 이렇게 다시 쓰라거나.

## 하는 일

- 실행 계획 트리 → 자연어 요약
- 안티패턴 탐지 → 인덱스 추천, 쿼리 재작성안
- 위험 경고 화면에 이유와 대안 쿼리를 diff로 표시
- AI 출력 검증 + AST 검증 (STEP 4와 동일 원칙)

## 완료 조건

대표 슬로우 쿼리 각각에 대해 원인 설명과 개선안이 나오고, 그중 정해진 개수 이상이 EXPLAIN 예상 비용 감소를 실제로 보인다.

## 주의

**여기가 가장 과소평가되는 단계다.** EXPLAIN 해석과 튜닝 제안은 "AI에 던지면 되겠지" 싶지만, 실제로는 프롬프트 반복 실험이 오래 걸린다. 여유를 두라.
